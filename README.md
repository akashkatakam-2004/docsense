# DocSense — RAG-Based PDF Q&A System

DocSense is an AI web application that lets you have a conversation with any PDF document. Upload a PDF, ask questions in plain English, and get streaming answers with page references — powered by Retrieval-Augmented Generation (RAG).

---

## 🚀 Features
- ⚡ **Streaming answers** — Words appear one by one like ChatGPT (via SSE)
- 🔍 **Semantic search** — `all-MiniLM-L6-v2` finds related content even when words are different
- 💾 **FAISS saved to disk** — Sessions survive server restarts, no re-uploading needed
- 🤖 **Multi-model support** — Choose between 4 AI models powered by Groq
- 📄 **Page references** — Every answer shows which pages the information came from
- 🕐 **Auto cleanup** — Memory and disk freed after 30 minutes of inactivity
- 💬 **Chat history** — All Q&A pairs saved in sidebar with timestamps
- 📥 **Export chat** — Download your full conversation as a text file
- 📊 **Diagram viewer** — Visual diagrams for architecture questions

## 🧠 How It Works

DocSense uses **RAG — Retrieval Augmented Generation**:

```
Retrieval  →  Find the most relevant chunks from your PDF
Augmented  →  Add those chunks to the AI prompt as context
Generation →  AI generates an accurate answer from that context
```

**Step-by-step pipeline:**
1. **PDF Loading** — PyPDFLoader reads your PDF page by page, storing text and page numbers
2. **Chunking** — Text split into 1000-character chunks with 200-character overlap (no sentence lost at boundaries)
3. **Embeddings** — Each chunk converted to a 384-dimension vector using `all-MiniLM-L6-v2`
4. **FAISS Indexing** — Vectors stored in FAISS and saved to disk for persistence
5. **Retrieval** — Top 4 most semantically similar chunks fetched for your query
6. **Streaming** — Answer generated by Groq LLM and streamed token-by-token via SSE

## ⚙️ Architecture

```
User uploads PDF
      │
      ▼
PyPDFLoader → Text Chunking (1000 chars, 200 overlap)
      │
      ▼
all-MiniLM-L6-v2 Embeddings
      │
      ▼
FAISS Vector Store (saved to disk)
      │
  User Query
      │
      ▼
Similarity Search (top-k=4 chunks)
      │
      ▼
Groq API (Llama 3.3 70B)
      │
      ▼
SSE Streaming → Browser (token by token)
```
